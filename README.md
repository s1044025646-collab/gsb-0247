# 扑克牌型比较后端（TypeScript + Node.js + SQLite）

离线的德州扑克牌型分析与比较服务，只做 **API 与 CLI**，无前端、无在线对局、无胜率/下注/资金逻辑。
在 Windows 本地直接运行，不依赖 Docker、WSL、付费服务或外部在线 API。

## 功能范围

- 标准 52 张牌（无大小王、无万能牌）。
- 输入 5 张或 7 张互不重复的实体牌，输出：
  - 最佳五张组合（7 张时穷举全部 `C(7,5)=21` 个子集，**不使用贪心分组**）；
  - 牌型名称、用于比较的**等级向量**、简明中文解释；
  - 多份相同牌力的实体组合时，按固定牌序展示一份，并注明不影响平局判断。
- 多人模式：每人 2 张底牌 + 5 张公共牌，整体去重，返回**并列名次**；
  允许玩家完全使用 5 张公共牌（使用 0 张底牌）。
- 九种牌型：高牌、一对、两对、三条、顺子、同花、葫芦、四条、同花顺。
  - `A2345` 仅作为**五高顺子**；`QKA23` 等不成立；花色不打破平局。
  - 等级向量逐项比较，天然正确处理踢脚牌、两对高低对子顺序、
    七张中两组三条（葫芦选三条高者）与三组对子（取最高两对）。
- SQLite 持久化：牌例、参与者、规则版本与**不可变分析快照**；
  旧分析不会被后来修改的牌例覆盖（每次分析追加一条快照）。

## 环境要求

- Windows + Node.js **v22.3+**（推荐 v25，自带内置 `node:sqlite`，无需任何原生编译）。
- 本项目零运行时第三方依赖；仅开发依赖 TypeScript 与类型声明。

## 快速开始

```powershell
npm install
npm run build     # 编译到 dist/
npm test          # 构建并运行全部 35 个确定性测试
npm start         # 启动 HTTP 服务（默认自动选择空闲端口）
npm run demo      # 运行内置确定性 CLI 演示
```

- 指定端口：`$env:PORT=8080; npm start`（默认端口 0 = 操作系统分配空闲端口）。
- 数据位置：项目内 `data/poker.db`；可用环境变量 `POKER_DATA_DIR` 更改根目录。

## 牌面格式

统一公开格式：`点数 + 花色`，大小写不敏感（自动规范化）。

- 点数：`2 3 4 5 6 7 8 9 T J Q K A`（`T` 即 10）
- 花色：`C`(梅花) `D`(方块) `H`(红桃) `S`(黑桃)
- 示例：`AS`（黑桃A）、`TH`（红桃10）、`9d`（方块9）

## HTTP API

服务仅监听 `127.0.0.1`。响应均为 JSON。

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET  | `/health` | 健康检查 |
| POST | `/api/analyze` | 分析 5/7 张牌（不落库） |
| POST | `/api/compare` | 多人公共牌比较（不落库） |
| POST | `/api/import` | 导入牌例并保存不可变分析快照 |
| GET  | `/api/cases` | 列出全部牌例 |
| GET  | `/api/cases/:id` | 查看单个牌例 |
| GET  | `/api/analyses?caseId=:id` | 列出历史分析（可按牌例过滤） |
| GET  | `/api/analyses/:id` | 查看某次分析的完整解释与快照 |
| GET  | `/api/export` | 导出全部牌例与历史分析 |

### 示例

```powershell
# 分析七张牌（三组对子 -> 取 A、K 两对，Q 踢脚）
Invoke-RestMethod http://127.0.0.1:51645/api/analyze -Method Post `
  -ContentType 'application/json' `
  -Body '{"cards":["AH","AD","KS","KC","QH","QC","2S"]}'

# 多人比较：公共牌即皇家同花顺 => 全体并列、均使用 0 张底牌
Invoke-RestMethod http://127.0.0.1:51645/api/compare -Method Post `
  -ContentType 'application/json' `
  -Body '{"board":["TH","JH","QH","KH","AH"],"players":[{"id":"甲","hole":["2C","3D"]},{"id":"乙","hole":["9S","9C"]}]}'
```

### 错误码

| HTTP | code | 含义 |
| ---- | ---- | ---- |
| 400 | `INVALID_CARD` | 未知牌面（点数/花色非法、长度不对） |
| 400 | `CARD_COUNT` | 张数错误（分析须 5/7 张，公共牌 5 张，底牌 2 张） |
| 400 | `EMPTY_INPUT` | 未提供牌或玩家 |
| 409 | `DUPLICATE_CARD` | 实体牌在输入内或玩家/公共牌之间重复 |
| 404 | `NOT_FOUND` | 牌例或分析不存在 |

错误响应形如：`{"error":{"code":"DUPLICATE_CARD","message":"..."}}`。
重复牌等校验失败发生在入库之前，不会写入成功报告或分析快照。

## CLI

```powershell
# 分析 5 或 7 张
node dist/src/cli/index.js analyze "AH KH QH JH TH"
node dist/src/cli/index.js analyze "as ks qs js ts 2c 3d"

# 多人比较：公共牌 玩家id=底牌1,底牌2 ...

# 导入（落库，生成不可变快照）/ 查看解释 / 导出

node dist/src/cli/index.js explain 1

# 内置确定性演示（含公共牌最大牌型平局、一对踢脚差异、重启读历史）
node dist/src/cli/index.js demo
```

## 等级向量说明

向量第一项为牌型编号（0..8，越大越强），其后按比较优先级排列点数（2..14，A=14）：

| 牌型 | 向量 |
| ---- | ---- |
| 高牌 | `[0, 高, 次, 中, 次低, 低]` |
| 一对 | `[1, 对子, 踢脚×3]` |
| 两对 | `[2, 高对, 低对, 踢脚]` |
| 三条 | `[3, 三条, 踢脚×2]` |
| 顺子 | `[4, 顺高]`（A2345 顺高为 5） |
| 同花 | `[5, 高点×5]` |
| 葫芦 | `[6, 三条, 对子]` |
| 四条 | `[7, 四条, 踢脚]` |
| 同花顺 | `[8, 顺高]` |

两向量从左到右逐位比较；全等即平局，**不比较花色**。

## 测试覆盖

`test/` 使用 Node 内置测试运行器（`node --test`），全部为固定规则用例，无随机抽样：

- 九种牌型分类与严格强度排序；低 A 顺子（A2345=五高，QKA23 不成立）；
- 非连续同花；皇家同花顺；两对顺序；一对踢脚逐位；四条踢脚；
- 七选五：葫芦选择（两组三条）、三组对子、同花顺优先、低 A 顺子；
- 输入牌序无关、花色整体置换无关；比较的反对称性与传递性；
- 公共牌最大牌型平局、同对子踢脚差异、公共牌/底牌重复冲突、张数错误、0/1/2 张底牌；
- 快照追加不覆盖、重启后读取历史、重复牌不产生成功记录；HTTP API 端到端。

运行：`npm test`。

## 设计取舍与限制

- 仅实现需求内功能：不计算胜率/赔率、不模拟发牌下注、不管理资金、不建多人在线房间。
- 只分析“已给定”的牌，不补全未知牌。
- 实体牌全局唯一：多人模式下公共牌与所有底牌不能有重复（标准实体牌规则）。
- `node:sqlite` 在当前 Node 版本会打印一条实验性警告，功能稳定可用；不影响结果。
